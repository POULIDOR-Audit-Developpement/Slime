# Gemmes (high risk high reward) — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter la gemme — 4e type de bille à 250 pts, placée dans des zones mortelles des patterns T3-T5 — avec outil éditeur, intégration scoring/anti-triche et pool par défaut régénéré.

**Architecture:** Une gemme est une bille avec un flag `gem: true` (priorité `gem > gold > life`), comptée dans `theoPts` comme les autres collectibles — donc `decode.html`, crypto et ranking restent intacts. Le générateur du pool par défaut pose des gemmes dans ses patterns T3-T5 après la génération des plateformes (mêmes tirages RNG en amont → patterns existants inchangés).

**Tech Stack:** JS vanilla (litecanvas), tests Node (harnais mini-DOM / stubs litecanvas existants), génération seedée maison.

**Spec:** `docs/superpowers/specs/2026-09-30-gemmes-design.md`

## Global Constraints

- `GEM_PTS = 250` (constante à côté de `GOLD_PTS` dans js/game.js).
- Priorité effective d'une bille : `gem` > `gold` > `life` > simple — collecte ET dessin.
- Une gemme ne donne JAMAIS le bonus de saut doré (`goldT` reste exclusif à `b.gold`).
- Aucune entrée UNLOCK_T pour les gemmes ; aucun changement à `js/crypto.js`, `decode.html`, `js/ranking.js`, au format `slime-patterns@1`.
- Rendu 100 % vectoriel par frame (pas de canvas généré) — règles perf AGENTS.md.
- Tout `js/*.js` modifié → bump `?v=` dans play.html et editor.html (Task 4).
- Régénération du pool : `node tools/gen_defaults.mjs 6 20260930` (mêmes params que le fichier actuel — voir en-tête de js/patterns-defaults.js).
- Libellés UI en français, ton de l'existant (« bille dorée (50 pts) » → « gemme (250 pts) »).

## Review Focus

1. **Gemme qui donne le saut doré** — un joueur ramassant une gemme ne doit pas recevoir `goldT`/charge aérienne. → Test game_sim Task 1 (`goldT === 0`).
2. **theoPts oublie les gemmes** — le « Possible » de decode.html deviendrait faux (impression de triche). → Test game_sim Task 1 (expected étendu de +240 par gemme).
3. **Flags or+gemme coexistants sur une bille** — doit être traitée comme une gemme seule, jamais les deux. → Test game_sim Task 1 (`goldsCollected === 0`, `gemsCollected === 1`).
4. **Flag perdu à la re-sérialisation** (vieil éditeur/round-trip JSON) — exporter puis ré-importer un pattern gemmé doit conserver `gem: true`. → Test editor_dom_test Task 2.
5. **Régénération qui déplace les patterns existants** — plateformes et billes simples du pool doivent rester identiques. → Task 3 : test déterminisme (double build → JSON identique) + `git diff` du Step 4 (ajouts de gemmes seulement).

Fonction au niveau de `simSpawnBalls` (seed-déterministe, appelée dans `build()` APRÈS la revalidation `reachOk` ligne ~189 et avant la conversion `ballsRel` — ainsi les tirages de plateformes ne bougent pas d'un pixel) :

```js
// Gemmes high-risk (spec 2026-09-30) : T3 ~1 pattern/3 (1 gemme), T4 ~1/3
// (1-2), T5 ~1/2 (1-3). Spots mortels uniquement : au ras des pics, en
// apex de gap, en hauteur au-dessus d'une plateforme large. Appelée après
// validation de la chaîne : aucun tirage en amont n'est déplacé.
function simSpawnGems(A, chain, balls, tier) {
  if (tier < 3) return
  const share = tier === 5 ? 0.5 : 0.34
  if (A.rand() >= share) return
  const nMax = tier === 5 ? 3 : (tier === 4 ? 2 : 1)
  const spots = []
  for (const p of chain) {
    if (p.spike) spots.push({ x: p.x + p.w * 0.5, y: p.y - 16 })
    if (p.type === 'basic' && p.w >= 4 * CELL) spots.push({ x: p.x + p.w * 0.5, y: p.y - 26 })
  }
  for (let j = 1; j < chain.length; j++) {
    const a = chain[j - 1], b = chain[j]
    if (b.x - (a.x + a.w) >= 2 * CELL) spots.push({ x: (a.x + a.w + b.x) / 2, y: Math.min(a.y, b.y) - 24 })
  }
  if (!spots.length) return
  const n = Math.min(A.randi(1, nMax), spots.length)
  const picked = []
  for (let k = 0; k < n; k++) {
    const s = spots.splice(A.randi(0, spots.length - 1), 1)[0]
    if (picked.some(q => Math.abs(q.x - s.x) < 6 * CELL)) continue
    picked.push(s)
    balls.push({ x: s.x, y: clampN(s.y, CEIL + 14, 252), gem: true })
  }
}
```
